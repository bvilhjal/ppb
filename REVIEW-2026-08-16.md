# Review of ppb — 2026-08-16

Reviewed at commit `5d2d680` ("Add LDpred3 adapters, public V7 diagnostics, and
the finite-sample correction"), clean working tree. Scope: full read of the
mathematical core (METHOD, CROSS_ANCESTRY, NOTATION and the estimator, LD,
harmonization, diagnostics, sumstats, simulate, score-distribution modules), a
full test-suite run, independent numerical spot-checks of three numbered
results, an audit of tests/experiments, an audit of scripts/results/REAL_DATA,
and an audit of the prior review trail.

## Verdict

The mathematics is correct, the engineering is fail-closed almost everywhere,
and the documentation is more honest than most published papers in this area.
No issue found undermines the validity of the estimator itself. What the review
finds instead is a gap between what is *measured* and what is *claimed
reproducible*: the flagship cross-ancestry application has never touched real
non-European data; the published EUR numbers cannot be regenerated from the
repo (unversioned inputs); and the "each experiment is encoded as a test"
pattern encodes single-seed Monte Carlo snapshots whose thresholds were chosen
after seeing the numbers, in places with margins under 5%.

## What this review verified independently

1. **Test suite**: 536 passed, 30 skipped in 47 s (conda env `ldpred3`, Python
   3.14.6). The 30 skips are 2 parametrized, machine-local skips in
   `tests/test_results_registry.py` (no current/legacy fit data in this
   checkout) × 15 parameter combinations — by design, not coverage loss.
   Note `pytest` in the default shell Python (anaconda 3.10) cannot even
   collect the package (`requires-python >= 3.11`); only the conda envs run it.
2. **(M2) in-sample identity**: reproduced to 1.1e-15 relative error in a fresh
   simulation (500 individuals × 300 variants), far inside the shipped 1e-10
   tolerance.
3. **(X3) finite-sample correction**: simulated 4000 replicates at N = 2000;
   mean raw bias +0.00047 against the predicted (1−R²)/N = 0.00050; the
   correction reduces it to −0.00003; the delta-method SE 0.00317 against an
   empirical SD of 0.00332. The formula, the subtraction, and the SE behave as
   `docs/METHOD.md` §1.3 states.
4. **(G3) sign-flip null**: closed-form `null_mean` matches a 20,000-draw
   Monte Carlo to 1.2% (Monte Carlo noise).
5. **Core-code reading**: the V4 joint-support rule, the gauge handling for
   `dosage`/`frozen` weights, the per-block PSD rejection with its
   `O(eps·m·||w||²)` tolerance, the Lanczos upper-bound asymmetry, the
   `lowrank_ld` rank-extension loop, and the score-distribution mean under
   allele swap (`2(1−f)` with negated weight) were each checked by hand and
   are correct as documented.

## Strengths worth keeping

- **Prior-art honesty.** The identity is credited to lassosum pseudovalidation
  (Mak et al. 2017) and the quasi-correlation of Pattee & Pan (2020), with
  PUMAS named as the same estimand by subsampling. The cross-ancestry framing
  is claimed as "still to be checked" rather than asserted novel.
- **The (H1)–(H3) framework** (one population, independence, one gauge) turns
  every documented failure mode into one of three violated hypotheses with a
  measured direction of error — a genuinely useful contribution.
- **Theorem 1 is correct.** The impossibility proof (varying the scale of
  `beta_B` leaves every A-side quantity and `Sigma_B` fixed while scaling the
  numerator) is valid, and the "second freedom" exercise (direction at fixed
  `h²_B`) correctly identifies the per-variant effect map as what `r_g` fails
  to pin down.
- **Fail-closed discipline.** Per-block PSD rejection, duplicate-variant
  rejection, joint-support zeroing, `cross_ancestry_eval.py` exiting 2 rather
  than inventing a number, refusal of pre-shrunk/LR8 LDpred3 caches, registry
  rejection of non-finite JSON and corrected-R² rows. Each refusal is tested.
- **Gold truth never comes from the code under test**: validations always use
  `np.corrcoef` on held-out individuals. Seeds are universal.
- **Withdrawals are disclosed, not hidden**: the liability-scale (M6) and
  overlap-correction removals are recorded in NOTATION.md §5 and
  FINISHING_PLAN.md with dates.

## Findings

Findings are consolidated from this review's own reading and from three
sub-audits (tests/experiments; scripts/results; review trail). Severity is
calibrated to the project's stated stage: "validated in simulation; not yet
run on real cross-ancestry data."

### Major — scientific and validation

**F1. The flagship application has never been exercised end-to-end, and the
simulation does not cover the real path's hardest step.** Phase 4 (real
`(z_B, D_B)`) is unmet by design, but the simulations also never exercise the
`--weight-scale dosage` × target `genotype_sd` conversion the real CLI
requires: everything is simulated within-cohort standardized, so `w`, `z_B`,
`D_B` share a per-cohort gauge by construction. The `r_g = 1` control
(portability 0.998) is documented as an LD-channel statement
(`docs/CROSS_ANCESTRY.md` "What this table does *not* show"), but the
standardization channel neutralizes the allele-frequency channel on score
variance as well, so the control is conditional on more artifacts than the
docs say. Both the missing run and the gauge prerequisite (a B-side LD
reference carrying **empirical** genotype SDs, not HWE) are already named in
the plan; the simulation gap is not.

**F2. Cross-ancestry novelty remains unchecked** (`docs/CROSS_ANCESTRY.md`
background admits this). Cross-population constructors (PRS-CSx and
derivatives) tune on target-ancestry data, and criteria of this family are the
natural validation yardstick there. Before any manuscript claim of "new," a
systematic sweep of PRS-CSx/XPASS/CT-SLEB/MUSSEL and the trans-ancestry
validation literature is required. This is the single highest-leverage open
scientific item.

**F3. Encoded experiments are single-seed snapshots with thin margins.**
Measured (re-running the shipped drivers read-only at the tested
configurations): `test_cross_ancestry.py:36` `ld_ratio > 1.02` observes 1.0274
at seed 1 (a 0.7% margin); the headline mismatch bias itself moves from −4.42%
(seed 0) to −0.96% (seed 1) and −5.44% (seed 3) across seeds;
`test_pumas.py:195` `<= 0.03` observes 0.0287 at seed 1; `test_figure_s1.py`
sees the independent-reference bias flip sign across seeds. No experiment
reports dispersion across seeds; `experiments/README.md` Tables 1–10 are
one-seed point estimates. The suite's false-pass probability against a real
regression is therefore unknown and sometimes small. Fix: replicate ≥5 seeds,
assert on mean ± SE-derived bounds, and record the margins.

**F4. Two validations run inside their own working model.**
`experiments/pumas_agreement.py` uses the Gaussian genotype generator for
which its moment covariance `V = var_y·D + zzᵀ` is exact — every other
simulation in the repo uses the diploid 0/1/2 simulator; one leg on the
diploid simulator is needed. `experiments/z_calibration.py`'s deflation sweep
applies exactly the uniform `chisq/λ` rescaling the correction assumes and
never simulates stratification (which raises the intercept and breaks (C3));
its one-sided conservatism claim is asserted, not tested. A related prose/test
mismatch: "at 2,000 variants the intercept's SE exceeds 1"
(`z_calibration.py` docstring) vs the tested bound `> 0.3` vs measured
0.77–1.00 — reconcile the three.

**F5. The published EUR numbers are not reproducible from the repo.** Only the
9 Pan-UKB files are checksummed (`scripts/panukb_checksums.tsv`, enforced by
the downloader and a manifest test — genuinely well done). The consortium GWAS
(GIANT/GLGC/CARDIoGRAM/DIAGRAM/BCAC), the PGS weight files, and the Google-
Drive half of the bigsnpr LD reference have no versioning, checksums, or
recorded accessions; `data/` is gitignored; the registry records no input
hashes or dependency versions; `REAL_DATA.md` Tables 3–4 rest on live PGS
Catalog API fetches with no committed snapshot (and a hard-coded dev-machine
CA path at `scripts/anchor_validation.py:49`). The "reproducible from
committed code" claim in `docs/REAL_DATA.md` is false in practice. Fix: an
input manifest (accession + checksum + date) and registry fields for input
hashes and package versions; commit a dated `results/anchor-*.json`.

**F6. Registry provenance gaps that scale the numbers.** The effective sample
sizes for binary consortium traits (163123 / 88810 / 254739) are hard-coded
with no recorded case/control derivation, and the registry labels them
"trait-level constant in the sumstats file" — true of the intermediate file,
but the constant was injected by `consortium_prep.py`, not read from the GWAS.
Since `z = t/√(t²+n−2)`, these constants directly scale R² (REAL_DATA.md
itself quantifies a 1.2× T2D swing). The pack also predates the jackknife,
(X3), and (C2) diagnostics; it should be regenerated now that they exist
(identified in the plan, still open).

### Major — test-suite mechanics

**F7. Seed-pinned fragility and pack-pinned tests.**
`experiments/pc_adjustment.py` crashes on `seed=1` (`input has a constant or
numerically constant column`) because `ppb.simulate._standardize_cols`
silently maps `sd==0 → 1.0` for monomorphic columns while the experiment's
stricter standardizer rejects them — CI never sees this, and the same
inconsistent degenerate-column policy will bite real low-MAF data.
`tests/test_results_registry.py` hard-codes the current pack (the rendered
string "91.8% target support"; positional `RECORDS[1][1]` indexing), so any
legitimate registry update breaks schema tests for non-schema reasons.

**F8. Overlap gates are author-chosen constants verified at two corners.**
The status logic turns on `max_vif=2.0`, `max_condition=5.0`, `detection_z=3.0`
etc., and the tests verify that the simulation landed in the refusal region
the gate defines rather than sweeping the architecture-vs-gate boundary —
notable because an earlier configuration produced the opposite qualitative
conclusion (disclosed at `experiments/overlap_detection.py:14–22`). The
mechanism validation (Hutchinson basis vs analytic trace) is not in question.

### Minor

1. `docs/README.md:138–141` is one commit stale: it still calls (X3) "the
   outstanding v0.1 completion criterion"; NOTATION.md §5 and METHOD.md now
   (today) record it as implemented in `ppb.estimator.corrected_r2`.
2. `scripts/build_leaderboard.py` enforces only structural schema rules;
   field-level violations crash (`KeyError`) in `row()` instead of being
   rejected cleanly — the schema.md promise is enforced only by the test file.
3. `scripts/panukb_download.sh` uses GNU `md5sum --check --status`; on macOS
   (BSD) validation fails and the script errors after downloading. Document or
   make portable.
4. Stale names: `panukb_filter_hm3plus.py`'s usage string names
   `filter_to_hm3plus.py`; REAL_DATA.md says weights arrive `.txt.gz` while
   `regenerate_results.py` reads them uncompressed; the overlap "honest
   anchor" is the summary formula on independent sumstats rather than an
   individual-level `corrcoef`.
5. `scripts/consortium_prep.py` resolves rsID ties by first occurrence
   (deterministic but unreported) and drops malformed rows silently (no
   per-reason counts); harmonization loss reasons are conflated to aggregate
   `w_match`/`z_match` in the registry, losing the
   ambiguous/mismatch/unmatched distinction the report computes.
6. `mse_interpretable` defaults to `False` for `dosage`/`frozen` weights even
   when an empirical target `genotype_sd` has put `w` on an absolute scale;
   conservative, but arguably too strict. The `z` name collision
   (`SignFlipNull.z` = coherence statistic) is documented in NOTATION.md §4
   and is fine.
7. The estimator path has no empty-input test (`r2([], [], DenseLD(np.zeros((0,0))))`).
8. Environment: `requires-python >= 3.11`, dev env is conda `ldpred3`
   (3.14.6), but nothing in the repo says so; the default shell Python cannot
   run the tests. A one-line CONTRIBUTING note would save the next machine.

## Ranked recommendations

1. **Novelty sweep** (F2) before any manuscript: PRS-CSx, XPASS, CT-SLEB,
   MUSSEL, and trans-ancestry validation practice.
2. **Input manifest + registry provenance** (F5, F6): checksums and accessions
   for every non-Pan-UKB input; input hashes and package versions in each
   pack; a committed, dated anchor-validation snapshot.
3. **Multi-seed the encoded experiments** (F3, F8): replicate, report SEs,
   replace magic slack (`1.02`, `0.03`, `mismatch < indep − 1.0`) with
   SE-derived bounds; add the stratification arm and a diploid PUMAS leg (F4).
4. **Exercise the real gauge path in simulation** (F1): dosage weights ×
   target `genotype_sd` against within-cohort-standardized truth, before the
   first real cross-ancestry run; then build the B-side reference with
   empirical SDs and run Phase 4.
5. **Regenerate the registry pack** with jackknife, (X3), and (C2) fields;
   de-magic the registry tests while doing so (F7).
6. Small fixes: the eight minor items above.

## Assumptions and limits of this review

The real-data pipelines were not executed (inputs are not in the checkout), so
reproducibility was audited by reading, not by re-running. Seed-fragility
figures in F3 were measured at the tests' own (smaller) configurations. The
bigsnpr conversion was not verified against the real 1.44M-variant reference.
Sub-audit findings (tests/experiments, scripts/results, review trail) were
produced by exhaustive file reads with spot re-runs; every spot-check this
review performed itself is listed under "What this review verified
independently" above.
